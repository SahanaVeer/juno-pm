# Agent Workflow Spec (AWSpec) · Juno

_Module 5. Generated by `M5 - Agent Workflow Spec Builder.html`. Paste over `05-agentic-workflows/awspec.md`._

## Goal

Reduce the time and effort required to create evidence-backed PRD drafts by using AI agents to synthesize product inputs, while keeping the human Product Manager in control of the final decisions and output.

**Primary actor:** Human + Agent co-pilot

## Trigger

Activate when a Product Manager selects one or more product evidence sources (e.g., customer transcript, ticket, or email) and clicks “Generate PRD,” with at least one source containing usable product context.

## Steps & tools

**Pattern:** Hybrid (ReAct inside Planner-Executor)

| Step | Action | Tool / model | Guardrail |
|---|---|---|---|
| 1 | Ingest approved transcripts, tickets, emails, and product documents. | transcript.search(query, filters) · read-only; retrieve relevant customer/stakeholder transcripts. | Agent can READ: approved transcripts, product/support tickets, emails, product strategy documents, knowledge-base content, and source metadata. Agent can WRITE: PRD draft workspace only, and only after the PM explicitly approves the generated draft. Agent CANNOT: modify source systems, edit/delete transcripts or tickets, send emails/messages, change product strategy, publish a PRD, or make/finalize product decisions without PM approval. |
| 2 | Retrieve and validate relevant evidence from connected knowledge sources. | tickets.search(query, filters) · read-only; retrieve product/support tickets and feature requests. |  |
| 3 | Synthesize and structure evidence into user problems, themes, needs, and opportunities. | knowledge.search(query, filters) · read-only; retrieve approved product strategy, requirements, and documentation. |  |
| 4 | Draft an evidence-backed PRD with traceable source references and confidence levels. | email.search(query, filters) · read-only; retrieve relevant product/customer communications. |  |
| 5 | Return control to the PM to review, resolve conflicts, edit, and approve the final PRD. | evidence.get_source(source_id) · read-only; retrieve the original source for verification and citation. |  |
| 6 | _ | prd.create_draft(content, citations) · write; create a draft PRD only after PM approval; no publish/send capability. |  |
| 7 | _ | Key boundary: All source systems are read-only. Juno can only write a draft PRD, and the PM must explicitly approve anything before it is finalized or shared. |  |

**Schemas**

transcript.search → {results:[{id,text,timestamp,source,score}]}
tickets.search → {results:[{id,title,description,status,created_at,score}]}
knowledge.search → {results:[{id,title,content,source,score}]}
email.search → {results:[{id,subject,body,sender,timestamp,score}]}
evidence.get_source → {id,source_type,content,metadata}
prd.create_draft → {draft_id,status,content,citations}

**Memory (in or out of scope)**

- **Episodic:** In-scope: Sources retrieved, agent actions, evidence reviewed, insights generated, decisions made, and user/PM feedback during the current run.
Lifetime: End of run; cleared after the PRD draft is completed or the workflow stops.
- **Semantic:** In-scope: PM’s preferred PRD structure, formatting conventions, and recurring workflow preferences. Lifetime: Persistent across sessions and retrievable when generating future PRDs.
Out of scope: Customer-specific data, sensitive information, and one-time product decisions are not persisted.
- **Working:** In-scope: Current PRD request, active product context, retrieved evidence, source references, agent outputs, confidence scores, and PM feedback. Lifetime: Current workflow/session only; cleared when the run ends
- **External:** Transcript/meeting API (read) - retrieve customer and stakeholder conversations.
Ticketing system API (read) - retrieve customer issues, feature requests, and support tickets.
Knowledge Base / Product documentation API (read) - retrieve product strategy, requirements, and existing documentation.
Email API (read) - retrieve relevant product/customer communications.
PRD workspace API (write, human-approved only) - save or update the generated PRD draft after PM review.

## Human-in-the-loop

PM reviews and approves the evidence-backed insights and PRD draft before any recommendation is finalized or shared. Control returns to the PM whenever evidence is conflicting, confidence is below 70%, or the agent proposes a material product decision.

## Success & failure

- **Done when:** Success: PRD draft is generated with evidence citations and confidence scores, then handed to the PM for approval.
Failure: Required evidence is missing, inaccessible, or insufficient to support a reliable PRD draft.
Escalation: Evidence conflicts, confidence falls below 70%, or the agent identifies a material product decision requiring PM judgment.
Timeout: Stop processing if evidence retrieval or agent execution exceeds the defined workflow time limit, and return control to the PM with the partial results.
- **Fails safe when:** Agent can READ: approved transcripts, product/support tickets, emails, product strategy documents, knowledge-base content, and source metadata.
Agent can WRITE: PRD draft workspace only, and only after the PM explicitly approves the generated draft.
Agent CANNOT: modify source systems, edit/delete transcripts or tickets, send emails/messages, change product strategy, publish a PRD, or make/finalize product decisions without PM approval.
